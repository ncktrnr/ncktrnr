# Deployment – ncktrnr.com

Local development runs in ddev; production is GreenGeeks shared hosting,
deployed over rsync/SSH. This doc is the source of truth for how code moves.

## Environment map

| | Local (ddev) | Production (GreenGeeks) |
|---|---|---|
| URL | http://ncktrnr.ddev.site | https://ncktrnr.com |
| Docroot | `web/` | `/home/fairytal/public_html/ncktrnr.com` |
| Vendor | `vendor/` | `/home/fairytal/ncktrnr/vendor` |
| Config sync | `../config/sync` (repo) | `/home/fairytal/config/ncktrnr/sync` |
| Database | `db` on `db` (ddev-managed) | `fairytal_ncktrnr_prod` on `localhost` |
| DB settings from | `settings.ddev.php` (generated) | `settings.prod.php` (server-only) |
| SSH | – | alias `greengeeks-fairytales` (chi202.greengeeks.net, user `fairytal`) |

The server keeps a Composer web symlink `/home/fairytal/ncktrnr/web →
public_html/ncktrnr.com`, and the production `autoload.php` must contain:

```php
return require __DIR__ . '/../../ncktrnr/vendor/autoload.php';
```

## Settings architecture

`web/sites/default/settings.php` is committed and contains **no credentials**.
Its tail loads exactly one environment file:

1. `settings.ddev.php` – generated by ddev, loads when `IS_DDEV_PROJECT` is set
2. `settings.prod.php` – exists only on the server, loads everywhere else
3. `settings.local.php` – optional personal dev overrides, loads last, never
   deployed

`settings.ddev.php`, `settings.prod.php` and `settings.local.php` are all
gitignored and all excluded from deploys. This means settings.php could be
deployed by accident and production would still work – the failure mode that
used to blank the site is gone once `settings.prod.php` exists on the server
(see one-time step below).

## Day-to-day local work

```bash
ddev start                                             # boot the environment
ddev drush uli                                         # one-time login link
ddev npm --prefix web/themes/custom/ncktrnr_tw run watch   # Tailwind rebuild on save
scripts/pull-db.sh [--files]                           # refresh content from prod
ddev drush cex -y                                      # export config after admin changes
```

Config lives in `config/sync/` and is committed with the code that needs it.

## Deploying

```bash
scripts/deploy.sh --dry-run   # see what would change, changes nothing
scripts/deploy.sh             # the real thing
```

The script refuses to run unless you are on `main`, the tree is clean and
local main matches `origin/main` – so the path is: branch → PR → merge →
deploy. It then:

1. builds production vendor (`composer install --no-dev`) and theme CSS
2. rsyncs `vendor/`, `web/` and `config/sync/` to their server locations,
   excluding (and protecting from deletion): `autoload.php`, all
   `settings*.php`, `sites/*/files`, `.well-known`, `cgi-bin`
3. runs `drush deploy -y` on the server (updb + cim + cr in the right order)
4. verifies every known past failure mode: autoload path, DB host, absence of
   settings.local.php, drush bootstrap, and a final HTTP 200 from
   https://ncktrnr.com
5. reinstalls local dev dependencies

If any verification step fails the script stops with a red FAIL line – check
that item on the server before doing anything else.

## One-time production step (before the first deploy of the new settings.php)

Production currently manages its whole environment inside `settings.php` by
hand. Move the environment bits into `settings.prod.php` so the committed
settings.php becomes safe to ship:

1. SSH in: `ssh greengeeks-fairytales`
2. Create `public_html/ncktrnr.com/sites/default/settings.prod.php`
   containing the values currently at the bottom of the live `settings.php`:

```php
<?php

// Production-only settings – this file lives on the server and is never
// committed or deployed.

$databases['default']['default'] = [
  'database' => 'fairytal_ncktrnr_prod',
  'username' => 'fairytal_ncktrnr_user',
  'password' => '<copy from live settings.php>',
  'host' => 'localhost',
  'port' => '3306',
  'driver' => 'mysql',
  'prefix' => '',
];

$settings['hash_salt'] = '<copy from live settings.php>';
$settings['config_sync_directory'] = '/home/fairytal/config/ncktrnr/sync';
```

3. Deploy the new `settings.php` once, manually and deliberately:
   `scp web/sites/default/settings.php greengeeks-fairytales:/home/fairytal/public_html/ncktrnr.com/sites/default/`
4. Check the site still loads, then `drush cr`.

After this, the deploy script's excludes keep both files untouched forever.

## If the site goes blank

In order of likelihood:

1. `autoload.php` – must require `../../ncktrnr/vendor/autoload.php`
2. `settings.prod.php` present and readable, DB host `localhost`
3. `settings.local.php` must NOT exist on the server
4. symlink `/home/fairytal/ncktrnr/web` must exist
5. `ssh greengeeks-fairytales '/home/fairytal/ncktrnr/vendor/bin/drush --root=/home/fairytal/public_html/ncktrnr.com status'`
